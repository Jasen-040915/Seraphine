# 免费开源版构建与发行

需要 Windows x64 与 Python 3.12。先安装 `requirements-plus.txt`，再运行 `scripts/download_voice_model.py` 和 `build-plus.ps1`。

构建脚本使用经检查的 ASCII 路径联接，避免 Qt 构建工具在中文路径下丢失插件。默认输出 `dist/Seraphine`，其中包含主程序、独立按键服务、本地语音模型和许可证。可使用 `-OutputDirectory` 与 `-BuildDirectory` 分别指定输出和中间目录。

`certifi/cacert.pem` 是 HTTPS 必需的公共根证书，必须随运行包保留。打包器只对此精确路径保留 PEM 文件，其他私钥文件继续排除。生成最终 ZIP 后，打包器会在包含中文和空格的临时目录重新解压，使用隔离设置运行界面与公开语音样本自检；检查通过后才报告发行成功。

测试：

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests
```

应用支持 `--self-test-full --self-test-voice`，在隔离配置目录中渲染真实界面并识别捆绑公开语音样本。诊断模式不启动真实键鼠监听或麦克风。游戏内聊天接收仍需实际对局确认。

发行校验和打包会启动 `Seraphine.exe`，请在管理员 PowerShell 中运行这两步。

源码与发行包排除：虚拟环境、Git 元数据、构建缓存、日志、截图、个人配置、诊断状态、旧授权、支付订单、数据库和私钥。语音模型通过下载脚本获取，保留其原许可。构建工具参见 `scripts/package_portable.py`，公开发布工具以经过审查的 Git 跟踪文件生成匹配源码包。

发布时保留根 `LICENSE`、`readme.md`、`MODIFICATIONS.md`、`document/UPSTREAM_README.md`、依赖许可及相应版本源码。

## 发布更新

1. 将 `app/common/config.py` 的 `VERSION` 设为更高的三段纯数字版本号，例如 `1.1.5` 或 `2.0.0`，并更新修改说明。程序版本号、GitHub 标签和发布标题使用同一个版本号。
2. 运行测试和 `build-plus.ps1`，再校验、打包：

```powershell
.\.venv\Scripts\python.exe scripts/validate_free_build.py --output artifacts/1.1.5/validation.json
.\.venv\Scripts\python.exe scripts/package_portable.py --version 1.1.5 --validation artifacts/1.1.5/validation.json --output ../1.1.5.zip
```

3. 在 [GitHub Releases](https://github.com/Jasen-040915/Seraphine/releases/new) 建立草稿。以 `1.1.5` 为例，标签和标题均填 `1.1.5`，上传 `1.1.5.zip` 并填写本次改动。完整 ZIP 包含对应源码和文件校验清单。
4. 等上传完成后，发布正式 Release 并设为 Latest，不勾选预发布。客户端会核对 GitHub 提供的 SHA-256，只接受高于当前版本且文件完整的发布。

客户端通过已正式发布的 Release 检查更新。首次需要用户手动换用支持数字文件名的完整便携版，包含此前已收到旧打包 `free.7` 的用户。支持数字文件名的更新器也兼容原来的长文件名。

若构建提示原路径联接指向其他目录，可用 `-BuildAliasPath "$env:LOCALAPPDATA/SeraphinePlusBuildNew"` 指定一个尚未存在的 ASCII 路径。
